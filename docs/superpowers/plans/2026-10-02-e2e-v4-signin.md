## Context
The demo account switcher (`/review/demo-controls`, localStorage `pathways.demo.v1`), the prototype session keys (`pathways.prototypeSession`, `pathways.prototypeRole`), the `/login` page and `/collection/entry` (now redirects to `/collection`) are gone. ## Global Constraints
- Real sign-in only: `/staff/login` -> Email/Password -> "Sign In" -> `/auth/mfa` six `Digit N of 6` fields -> "Verify authenticator code".
- Accounts come from the local seed `apps/api/prisma/local-demo-seed.ts` (`@pathways.example`), prepared at runtime via the Supabase admin API exactly as `rbac-v4.spec.ts` `prepareActor` does. No credentials or secrets written to files.
- Specs needing the DB skip when the local DB container is not running (existing `hasLocalDb` pattern).
- Route-stub specs stay untouched: `mfa-access`, `role-routes`, `password-login`, `monitoring-read`, `signin-lockout`, `navigation`.
- Match existing style: no semicolons, single quotes, one-line one-sentence comments, no emojis, no new dependencies.
- Expectations per role must follow the v4 adoption doc and the actual app code (nav/permission maps under `apps/web/src`), not old demo behavior.
- Verify each spec you touch with `npx playwright test --config playwright.config.ts <file>` when the local stack is up (`pnpm db:local:start`, API on 4000); otherwise run `pnpm --filter @pathways/web exec tsc --noEmit -p tsconfig.json` (or the repo's e2e typecheck) and say the e2e run was skipped.
